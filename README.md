# 每日一记 (astrbot_plugin_daily_diary)

让 Bot 每天用大模型写一篇日记：定时自动生成、自动保存 TXT、自动存入 AstrBot 知识库、写成长期记忆，还可以由 Bot 自己发布到 QQ 空间。

## 功能特性

- ⏰ **发布时间自由设定**：24 小时制任意时刻（如 `08:00`、`21:30`），修改保存即生效
- 🧩 **缓存友好的提示词结构**：写作要求放在静态系统提示词里，字数/禁止内容/风格等稳定配置按固定顺序排在用户消息前部，每天变化的日期放在最后 —— 同一份配置下，跨天调用可命中大部分前缀缓存
- ✍️ **写作风格可自定义**：用一句话定义文风（如「温柔、爱写城市夜景，句子偏短」），只影响表达方式，不会改变人格身份；另外可填补充要求，支持 `{date}`、`{min_words}`、`{max_words}`、`{banned_words}` 占位符
- 🎭 **人格设定从 AstrBot 人格库中选**：在 WebUI 下拉选择已配置好的人格，日记必须严格遵循该人格的身份、口吻与价值观；写作风格与人格设定彼此独立
- 🛡️ **人格一致性自检**：发布前自动检查这篇日记是否符合所选人格，不符合会带着原因重写一次；仍不符合则该篇不入知识库、不写记忆、不发 QQ 空间（只存档），避免写出人设崩坏的日记
- 📏 **字数范围可设定**：超出设定范围（±30% 容差）会自动重写一次
- 🚫 **禁止内容可设定**：每行一条，支持正则；命中后自动重写，仍命中则拦截发布与入库
- 🤖 **大模型可指定**：可选服务提供商 + 模型 ID；不指定则使用 AstrBot 全局默认
- 📚 **知识库自由指定**：支持多个知识库，多选即可；日记自动分块、向量化入库
- 🧠 **长期记忆联动**：写完联动 [astrbot_plugin_livingmemory](https://github.com/lxfight-s-Astrbot-Plugins/astrbot_plugin_livingmemory) 把当天日记写成一条记忆，之后聊天时能被检索到
- 📄 **TXT 自动存档**：保存至 `data/plugin_data/astrbot_plugin_daily_diary/diaries/`
- 🌐 **QQ 空间自动发布**：写完联动 [astrbot_plugin_qzone](https://github.com/Zhalslar/astrbot_plugin_qzone) 插件自动发说说（Cookie/登录由该插件管理）
- 📢 **结果通知**：生成结果自动推送到指定会话（在会话里发一条命令即可绑定）
- ♻️ **漏跑自动补跑**：进程重启错过触发点时，启动后会检测当天是否已生成，未生成则自动补一篇

## 工作流程

```
定时触发（或手动 /diary）
   │
   ▼
组装提示词（静态系统提示词 + 用户消息：人格设定 → 字数 → 禁止内容 → 写作风格 → 补充要求 → 日期）
   │
   ▼
调用 LLM 生成日记 ──► 校验：字数范围 + 违禁内容 ──不过──► 尾部追加反馈重写一次
   │                                                    │
   ▼                                                    ▼
保存 TXT 文件                                    仍命中违禁内容？
   │                                              是 → 仅存档，终止
   ▼                                              否 → 继续 ↓
写入指定知识库（可多个）
   │
   ▼
写入 LivingMemory 长期记忆（可选）
   │
   ▼
发布到 QQ 空间（可选）
   │
   ▼
向通知会话推送结果摘要
```

## 安装

**方式一：WebUI 上传（推荐）**

1. 将本目录打包为 `astrbot_plugin_daily_diary.zip`
2. WebUI → 插件管理 → 从压缩包安装 → 上传

**方式二：手动放置**

把 `astrbot_plugin_daily_diary` 整个目录放入 `AstrBot/data/plugins/`，然后在 WebUI 插件页重载（或重启 AstrBot）。

> 无第三方依赖（`aiohttp`、`apscheduler` 均为 AstrBot 内置），无需 pip 安装。

## 配置说明

插件配置位于 WebUI → 插件管理 → 每日一记 → 配置。

### ⏰ 定时设置

| 配置项 | 默认值 | 说明 |
|---|---|---|
| 启用每日定时生成 | 开 | 关闭后仅可手动触发 |
| 每日生成时间 | `21:30` | 24 小时制 `HH:MM`，保存后即生效 |
| 定时触发所用时区 | `Asia/Shanghai` | IANA 时区名。Docker 部署的容器多为 UTC，保持默认即按北京时间触发，否则会差 8 小时 |
| 启动时补跑当天漏掉的日记 | 开 | 重启后若当天还没生成，60 秒后自动补跑 |

### 🤖 大模型设置

| 配置项 | 默认值 | 说明 |
|---|---|---|
| 服务提供商 | 空 | 下拉选择；留空使用 AstrBot 全局默认 |
| 模型 ID | 空 | 留空使用该提供商的默认模型（推荐） |
| 请求重试次数 | 1 | 单次生成内允许的重试上限，调小可让夜间超时更快失败并切换兜底提供商 |
| 补充要求 | 空 | 留空即用内置写作要求；填写后作为【补充要求】附在用户消息里（不影响前缀缓存） |
| 人格设定 | 空 | 下拉选择 AstrBot 已配置的人格（WebUI「人格」里维护）；留空或选中内置 `default` 时不使用人格设定 |
| 人格一致性检查 | 开 | 发布前多一次自检调用；不符合人格时带原因重写一次，仍不符合则不发布、不入库、不写记忆 |
| 写作风格 | 空 | 一句话定义文风，作为【写作风格】放进用户消息；只改表达方式，不改人格身份 |
| 字数下限 / 上限 | 200 / 400 | 正文按去除空白后的字符数计 |

补充要求里可用的占位符（均可不用，硬性要求会自动附加）：

| 占位符 | 替换为 |
|---|---|
| `{date}` | 中文日期，如 `2026年10月24日 星期六` |
| `{min_words}` / `{max_words}` | 字数下限 / 上限 |
| `{banned_words}` | 禁止内容列表（顿号分隔，无则替换为「无」） |

### 🚫 内容审核

| 配置项 | 默认值 | 说明 |
|---|---|---|
| 日记中禁止出现的内容 | 空 | 每行一条；可编译为正则的按正则匹配，否则按文本包含匹配 |

审核策略：命中 → 自动重写一次 → 仍命中 → 该篇**不发布、不入知识库、不写记忆**，仅本地存档并在通知中说明原因。

### 🧠 长期记忆（LivingMemory）

| 配置项 | 默认值 | 说明 |
|---|---|---|
| 把每天的日记写成一条记忆 | 开 | 需安装并启用 astrbot_plugin_livingmemory；未就绪时自动回退写入本地 `memories_fallback.jsonl` |
| 记忆重要性 | 0.6 | 0~1；日记属日常记录，建议 0.5~0.7 |
| 记忆作用域 | `livingmemory:global` | 默认全局；也可填某个会话的 unified_msg_origin |
| 记忆主题标签 | `日记` | 逗号分隔，会自动补上当天日期，最多取 5 个 |
| 记忆情绪标签 | `neutral` | 日记不额外判断情绪，保持默认即可 |

记忆内容是「日期 + 日记正文」，正文过长会截断到 800 字以内，避免占用过多记忆预算。

### 💾 存储设置

| 配置项 | 默认值 | 说明 |
|---|---|---|
| 存放日记的知识库 | 空 | 多选；需先在 WebUI「知识库」中创建并配置嵌入模型 |
| 保存 TXT 文件 | 开 | 存至 `data/plugin_data/astrbot_plugin_daily_diary/diaries/diary_日期.txt` |

### 🌐 QQ 空间发布

|---|---|---|
| 联动 astrbot_plugin_qzone 发布 | 关 | 开启后每次生成成功即发布 |

发布能力由 **astrbot_plugin_qzone** 插件提供，见下节。

### 📢 结果通知

| 配置项 | 默认值 | 说明 |
|---|---|---|

## 指令

| 指令 | 说明 |
|---|---|
| `/diary` 或 `/每日一记` | 立即生成今天的日记并走完整流程（仅管理员） |

## Token 与缓存优化

大模型的「命中缓存」取决于两次请求的前缀是否逐字节相同，因此本插件按下面的方式组织请求：

1. **系统提示词完全静态**：写作准则（真诚、有细节、严格遵循人格、直接输出正文等）常驻 `system_prompt`，不含日期、字数和任何配置项 —— 这些内容每天/每次都不变，是缓存的最长公共前缀。
2. **用户消息里「稳定在前、易变在后」**：顺序固定为【人格设定】→【字数】→【禁止出现】→【写作风格】→【补充要求】→【日期】，最后才是「请写今天的日记」。改配置时只有对应的一小段变化，改动风格不会让前缀缓存整体失效。
3. **日期放在最末**：唯一每天都变的内容被压到最后一行，跨天调用仍能命中前面所有内容。
4. **人格正文排在最前**：人格设定是所有人共用的稳定前缀，且篇幅最长（实测「张蕾」人设 5810 字），放在用户消息开头能让这段长文本被反复命中。
5. **重试只追加尾部**：字数、违禁或人格校验不过时，只在用户消息末尾追加「【重试】…上一次输出…」，系统提示词与前缀完全不变，重试请求可以直接复用上一次的缓存。
6. **人格自检独立前缀**：自检用另一段静态系统提示词（`PERSONA_CHECK_PROMPT`），与正文生成互不干扰，两段前缀各自复用缓存。
7. **单次重试上限**：默认 `request_max_retries=1`，夜间接口卡住时快速失败并切换兜底提供商，避免挂住整个定时任务。
8. **粘性兜底**：某次调用切换到兜底提供商成功后，后续生成会优先使用它，减少无效等待。

> 实测（DeepSeek 官方端点，3 首歌的听后感场景）：`prompt_tokens=276`，其中 `cache_hit=128`、`cache_miss=148`；稳定前缀被命中，只有每天变化的部分未命中。日记场景的静态前缀更长（约 300~400 token），命中比例会更高。

## 安全设计

- **提示词注入隔离**：日期、字数、禁止内容、写作风格都以固定标签拼装，用户填写的补充要求只能落在【补充要求】段内，无法改写系统提示词
- **人格约束**：人格正文由 AstrBot 的人格库提供，系统提示词明确人格优先级最高、写作风格不得改变身份；发布前再做一次一致性自检，充当最后一道闸门
- **违禁内容双保险**：先重写一次，仍命中则阻断发布与入库，只保留本地 TXT 以便人工复核
- **网络访问受限**：不引入额外依赖、不访问第三方接口，全部走 AstrBot 既有的 LLM 与知识库通道
- **记忆写入失败降级**：LivingMemory 未安装或接口异常时回退本地文件，不影响日记主流程

## QQ 空间发布：联动 astrbot_plugin_qzone

本插件不直接管理 QQ 空间登录，发布功能通过 [astrbot_plugin_qzone](https://github.com/Zhalslar/astrbot_plugin_qzone) 插件完成：

1. 在 AstrBot 插件市场安装 **astrbot_plugin_qzone**（QQ空间）并启用
2. 按该插件的说明完成 QQ 空间登录/Cookie 配置（配置都在它那边），并用它的 `/发说说` 命令确认能发
3. 回到本插件配置，打开「联动 astrbot_plugin_qzone 发布」开关
4. 发送 `/diary 状态`，QQ 空间一行显示「已联动 astrbot_plugin_qzone」即就绪

发布失败（Cookie 失效等）会在结果通知与日志中说明原因，更新 Cookie 请在 astrbot_plugin_qzone 的配置中操作。

## 二次开发指南

```
astrbot_plugin_daily_diary/
├── main.py             # 入口：指令注册、定时调度、流程编排（_run_diary 是主流程）
├── diary_generator.py  # 生成：提示词组装、LLM 调用、字数/违禁校验（generate 为主入口）
├── living_memory.py    # 记忆：把日记写进 LivingMemory（save_memory 为主入口）
├── qzone_link.py       # 联动：调用 astrbot_plugin_qzone 发布（publish_diary 为主入口）
├── metadata.yaml       # 插件元数据（名称、版本、兼容版本范围）
├── _conf_schema.json   # 配置模式（WebUI 配置面板由此生成）
├── requirements.txt    # 第三方依赖（当前为空）
└── README.md
```

常见扩展点：

- **换发布渠道**（如 Telegram 频道）：在 `main.py` 的 `_run_diary` 中把 `publish_diary(...)` 换成对应平台的调用即可；参照 `qzone_link.py` 的写法可对接任意其他插件
- **调整生成策略**：`diary_generator.py` 顶部的 `WORD_TOLERANCE`（字数容差）与 `MAX_RETRY`（重试次数）
- **调人格策略**：`resolve_persona`（怎么取人格）与 `PERSONA_CHECK_PROMPT` + `_check_persona`（自检的判据）
- **调提示词结构**：`SYSTEM_PROMPT`（静态部分）与 `build_user_prompt`（用户消息顺序）—— 调整顺序会直接影响缓存命中，改动前先读上面的「Token 与缓存优化」
- **接别家记忆插件**：在 `living_memory.py` 里替换 `get_lmem`/`save_memory` 的实现，主流程无需改动
- **换存档格式**（如 Markdown）：改 `main.py` 的 `_save_txt`
- **增配置项**：改 `_conf_schema.json` 后在代码中 `self.config.get(...)` 读取；AstrBot 会自动为老配置补默认值

核心 API（AstrBot v4.29）参考：

- LLM：`provider.text_chat(prompt=..., system_prompt=..., model=..., request_max_retries=...)`，`context.get_using_provider()` / `get_provider_by_id()` / `get_all_providers()`
- 人格：`context.persona_manager.get_persona_v3_by_id(id)`（同步，返回 `{"name", "prompt", ...}`）/ `get_persona(id)`（异步，查数据库）/ `get_default_persona_v3(umo=None)`
- 知识库：`context.kb_manager.get_kb_by_name(name).upload_document(file_name, file_content: bytes, file_type)`
- 主动推送：`context.send_message(unified_msg_origin, MessageChain(chain=[Plain(text)]))`
- 记忆：LivingMemory 的 `engine.add_memory(...)` 与 `processor.build_memory_from_structured_data(...)`，见 `astrbot_plugin_livingmemory`

## 常见问题

**Q：生成失败提示「未找到服务提供商」/「尚未配置任何大模型服务提供商」？**
检查插件配置的提供商 ID 是否正确，或在 AstrBot 全局设置中配置默认提供商。

**Q：知识库写入失败？**
确认知识库已在 WebUI「知识库」中创建，且已选择可用的嵌入模型（Embedding Provider）；用 `/diary 状态` 可查看当前可用的知识库列表。

**Q：状态里显示「已开启但未检测到 LivingMemory」？**
说明 astrbot_plugin_livingmemory 未安装或尚未初始化完成；此时日记会写入本地 `memories_fallback.jsonl`，装好插件后重启即会自动接管。

**Q：QQ 空间发布失败「未找到已启用的 astrbot_plugin_qzone」？**
安装并启用 astrbot_plugin_qzone 插件，且完成其登录配置；用 `/diary 状态` 检查联动是否就绪。

**Q：QQ 空间发布失败提示 Cookie 相关？**
登录态由 astrbot_plugin_qzone 管理，请到该插件的配置中更新 Cookie/重新登录，与本插件无关。

**Q：字数总是不达标？**
字数统计为去除空白后的字符数；模型对字数控制有限，插件在超出 ±30% 容差时会重写一次，仍偏差则接受并在通知中标注。可适当放大设定范围或更换字数控制更好的模型。

**Q：定时到点没有触发？**
用 `/diary 状态` 查看下次运行时间；进程重启后若错过触发点，启动时会检测当天是否已生成，未生成则 60 秒后自动补跑。手动验证可用 `/diary`。

**Q：怎么确认缓存真的命中了？**
看 AstrBot 日志里该提供商的 usage 字段（如 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`）。首次调用必然全部未命中，同一配置下第二天的调用应能看到命中。

**Q：状态里显示「人格：未指定」？**
说明插件配置的「人格设定」为空，或者 AstrBot 里选中的是内置 `default` 人格（通用英文助手设定，不适合直接拿来写日记）。到 WebUI「人格」里新建/选择一个人格，再回到插件配置里下拉选中它即可。

**Q：日记被判「不符合人格设定」而没有发布？**
说明发布前的自检认为这篇日记与人格不符（状态与通知里会带上原因）。插件已经带着该原因重写过一次，仍不通过才会拦截。可检查人格正文是否写得过于笼统、或字数/禁止内容要求是否与人格设定冲突；也可以临时关闭「人格一致性检查」。
